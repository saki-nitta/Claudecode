# /podcast-batch — ポッドキャストノートを複数本まとめて並列生成する

## 背景

毎週のポッドキャストルーティン（[毎週水曜：オリジナルポッドキャスト作成手順.md](D:\Obsidian_Sync\リモート保管庫1\08_手順\毎週水曜：オリジナルポッドキャスト作成手順.md)参照）で、
テーマ深掘りノートを複数本（基本10本）まとめて作る。
リサーチ・執筆はサブエージェントの中で完結させ、メインの会話には保存報告だけを残す（トークン節約）。

## 対象ファイル

- テーマ候補ストック: `D:\Obsidian_Sync\リモート保管庫1\08_手順\毎週水曜：オリジナルポッドキャスト作成手順.md`
- 保存先: `D:\Obsidian_Sync\リモート保管庫1\05_発信\podcast\`（フォルダが無ければ作成）

## 手順

1. テーマ候補ストックを読む。10カテゴリ（クラファン・販売／木育・おもちゃ市場／子育て支援・地域活動／事業運営・EC・D2C戦略／AI・ツール活用／補助金・資金調達／海外事例／ワークショップ／アップサイクル／遊び・発達心理学）から、未消費（`- [ ]`）の項目をカテゴリごとに数える（2026-09-29改訂：「地域・社会起業」廃止、「事業運営・ブランディング」→「事業運営・EC・D2C戦略」に改称、「補助金・資金調達」「遊び・発達心理学」を新設、「海外のおもちゃ市場・海外事例」→「海外事例」、「ワークショップ・体験プログラムのアイデア」→「ワークショップ」に改称）。
   - 10カテゴリ×週10本のため、基本は**各カテゴリから1本ずつ**選ぶ（2026-09-29〜。特定カテゴリのみ最低1本という個別ルールは廃止）。
   - 「木育・おもちゃ市場」は読者が木育の基本知識をすでに持っている前提で選ぶ（「木育とは」等の入門的なテーマは選ばない）。東京おもちゃ美術館関連の事例（おもちゃ学芸員モデル等）は複数週で扱い済みのため選ばない（2026-09-18〜）
   - 「AI・ツール活用」は読者がClaude・ChatGPT・Gemini・NotebookLM等の複数AIを日常業務で併用している前提で選ぶ（「AIとは」「導入の始め方」等の入門的なテーマは選ばない。複数AIの使い分け・連携ワークフロー・実務活用の深掘りを優先）（2026-09-18〜）
   - 「だれでも通園制度」は除外テーマ。選ばない（2026-09-29〜）
   - ユーザーが本数やテーマを指定した場合はそれに従う（以下は基本10本の場合の流れ）
2. **在庫チェック：** 未消費の合計が目標本数（デフォルト10）に満たない場合、AskUserQuestionで「在庫が◯本しかない。どうする？」と確認する。選択肢の例：
   - 涼子が新テーマを補充して目標本数まで作る（推奨）
   - 在庫にある分だけ今週作る
   - サキがテーマを指定する
   - 「補充する」が選ばれたら、在庫切れ／少ないカテゴリを中心に、既存の消費済みテーマと重複しない新テーマ候補を考え、Editツールでストックファイルの該当カテゴリに `- [ ]` 未消費項目として追記する（10カテゴリのバランスを見て、目標本数に届く数だけ追加）。
3. 選んだテーマ数だけ、Agentツールを**1メッセージにまとめて呼び出し、並列実行**する。`subagent_type: general-purpose`。各呼び出しのプロンプトは以下を埋めて自己完結させる（会話の前提は共有されないので、必要な情報は全部書く）：

   ```
   木のおもちゃ事業・地域活動・子育て支援に取り組む小規模事業者向けの
   ポッドキャスト深掘りノートを1本作成して保存するタスク。

   テーマ：【{{テーマ}}】

   手順：
   1. Web検索で本テーマに関する直近1ヶ月以内の記事・事例を3件収集する
      （特徴だけでなく「なぜ今注目されているか」も含める）。テーマが海外事情・海外ブランド事例の場合は、
      日本語記事に限定せず英語の一次情報（海外メディア・ブランド公式サイト等）を積極的に使うこと。
   2. 以下の構成で4,000字以上のノート本文を書く：
      背景→現状→事例→小規模事業者への示唆→行動提案
      重要：対談台本・スクリプト形式は絶対に書かないこと。あくまで調べた内容を詳しく正確にまとめた
      リサーチノート（地の文）にすること。NotebookLM側が音声対談を自動生成するため、
      素材となる情報密度の高い文章のみが必要。
      重要：ノート本文中に「とうめいしっぽ」という社名や、特定個人の実名・実際の経歴等、
      実在する事業者・個人を特定できる情報を一切書かないこと（一般化した「小規模事業者」
      「木のおもちゃ事業者」等の表現に留める）。NotebookLMが音声化する際、実在の事業者名が
      入っていると架空の詳細を事実であるかのように話し始めてしまうため。
      言語：基本は日本語で書く。ただし海外テーマで英語の一次情報が中心の場合は、ノート本文を英語で書いてよい
      （NotebookLMは英語ソースからでも日本語の音声対談を生成できるため問題ない）。
   3. Writeツールで以下のパスにファイルを保存する：
      D:\Obsidian_Sync\リモート保管庫1\05_発信\podcast\{{YYYYMMDD}}_doc_podcast-{{テーマ}}_draft.txt

      ファイル内容のフォーマット：
      ---
      date: {{YYYY-MM-DD}}
      tags: [ポッドキャスト, {{テーマ}}]
      status: draft
      ---
      # {{テーマ}}

      （本文）

   最後の返答は「保存完了：ファイル名＋1行サマリ」のみにすること。本文をそのまま返さないこと。
   ```

4. エージェントが「session limit」等のAPIエラーで中断された場合、未完了のテーマだけを同じ手順で再実行する（成功済みの分はスキップ）。
5. 全エージェントの保存が完了したら、テーマ候補ストックの選んだ項目（新規追加分含む）に `- [x]` と実行日をつける。
   - Editツールで複数箇所を1メッセージ内で並列編集すると稀に「String not found」で失敗することがある。失敗したら1件ずつ・直前にファイルを再読み込みしてから編集し直す。
6. ユーザーには保存したファイル名一覧と1行サマリだけを報告する（本文は貼らない）。NotebookLMへのソース追加・音声生成はユーザー側の作業なので涼子は行わない。

## 使い方

ユーザーが「ポッドキャスト10本作って」「今週分のポッドキャストお願い」などと言ったら実行する。
在庫が十分にあれば確認なしで実行、在庫不足時はStep 2の確認を挟む。
本数や個別テーマの指定があればそれに従う。
